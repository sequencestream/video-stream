# 待实现功能

本文基于当前代码、架构文档和测试状态整理。项目的核心数据模型、任务编排和多数规则引擎已经具备，但默认运行路径仍大量使用 stub；近期目标应是先形成一条能生成真实、可播放 MP4 的端到端链路，再逐步补齐外部平台能力。

## P0：打通真实生产闭环

### 1. 修复向导中的工程持久化

- [x] `completeScript` 在启用 CostWarden 时仍须调用 `SaveProject`。
- [x] 增加 Step 1 → Step 7 的向导集成测试，确保脚本定稿后 Step 5 能读取工程。
- [x] 覆盖失败步骤的 `resume`、服务重启后的会话恢复和重复提交幂等性。

向导写操作通过持久化 operation journal 和 session version 防止重复计费、并发串步；服务重启将中断操作转为可显式续跑的失败状态。

### 2. 实现最小可用的真实渲染链路

- [x] 实现真实 FFmpeg 执行器，替换默认 `StubFFmpeg`。
- [x] 实现可用的 TTS provider，输出真实 WAV/PCM 和词级时间戳（使用 edge-tts 测试验证）。
- [x] 先支持本地图片/视频 + Ken Burns + motion graphics，生成每个 seg 的真实画面。
- [x] 实现音视频拼接、缩放、转码、转场和 MP4 mux。
- [x] 实现软字幕；随后补充 FFmpeg 字幕烧录。
- [ ] 实现真实 LUFS 测量与响度归一化。
- [ ] 实现定稿后的 BGM 卡点与混音。
- [ ] 输出后校验容器格式、分辨率、时长、音轨和可解码性；失败时拒绝交付。

建议最小路径：`真实 TTS → 本地/授权素材 → Ken Burns → 软字幕 → FFmpeg → 可播放 MP4`。AI 视频生成可在该路径稳定后接入。

### 3. 让增量重编译真正驱动渲染

- [ ] 将 `recompile.Plan` 的结果传入渲染执行器。
- [ ] 未失效 seg 直接复用 artifact，只重新生成 invalidated seg。
- [ ] 复用前同时检查 `render_cache_key` 和实际时长是否落在 `duration_budget` 内。
- [ ] 正确处理全量重跑的六条边界。
- [ ] 持久化缓存命中数、重生成数、真实耗时、实际成本和节省成本。
- [ ] 增加“只改一个非边界 seg，仅生成失效子树”的端到端测试。
- [ ] 基于至少 20 次真实编辑记录评估失效率，超过 40% 时重新评估该方案。

## 暂不实现

以下内容与当前本地优先 MVP 的目标不一致，或风险明显高于收益，暂不进入近期排期：

- 云端多租户、用户体系、团队凭据共享和云端计费。
- Kubernetes 部署和分布式任务编排。
- 全网热点爬虫、浏览器 cookie 抓取、评论自动回复和评论正文持久化。
- 全局最佳发布时间预测和自适应热点阈值。
- 自动放宽合规闸门或关闭 AI 生成标识。
- 在真实编辑数据充足前配置化增量重编译边界或调整 40% 阈值。
- 在基础向导可用前建设复杂的专业时间轴编辑器。

## 推荐里程碑

1. **M0：流程可继续**——修复工程持久化，Step 1 → Step 7 集成测试通过。
2. **M1：真实可播放**——真实 TTS、本地素材和 FFmpeg 产出可播放 720p/1080p MP4。
3. **M2：增量有效**——编辑一个 seg 时只重生成失效子树，并记录真实节省成本。
4. **M3：内容可用**——接入真实脚本 Agent、素材 provider 和完整 WebUI 操作。
5. **M4：输入与交付完整**——ASR/降噪、官方雷达 source、容器标识和真实发布稳定运行。
